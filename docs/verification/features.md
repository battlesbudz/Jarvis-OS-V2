## Approved memory in conversations

Explicit `remember …` requests create a local **pending** proposal after the current raw action request has been parsed. A user must approve it in Memory before it can be retrieved. On later chat or voice turns, the runtime retrieves only approved, non-expired lexical matches and seeds the bounded JSON-quoted packet as historical, untrusted model context after action authorization; it cannot authorize tools or override the current request. Ledger deletion/correction, selected-model changes, a changed packet, and storage/retrieval failures reset the native conversation context. Storage failures are shown as an honest response and no memory is used. `ConversationMemoryTest` covers review, invalidation, malformed storage, and non-requests; `test24_memoryManagerReviewsCorrectsSearchesAndErases` covers the release UI review contract. This does not verify real-model recall quality.

Voice and Chat are display surfaces for the same call. The production tab callback dispatches no end action; End Call and recognized stop controls remain termination paths. `VoiceNavigationPolicyTest` and `test25_voiceNavigationRetainsCallIdUntilExplicitEnd` exercise the controller/policy boundary, not mounted Compose navigation or physical audio capture. Active-call Chat tab behavior and quiet-capture rearm remain release/device checks. Continuous accepted-action queue behavior remains covered by test20–test23.
